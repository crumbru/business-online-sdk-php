## 1. Superpowers — обязательный процесс

Перед любым ответом или действием загрузите `using-superpowers`.

- OpenCode: инструмент `skill`; Codex: `/skills` или `$using-superpowers`.
- Новая функциональность — `brainstorming`, затем `writing-plans`.
- Реализация — `test-driven-development`, если есть что тестировать; баг — `systematic-debugging`.
- Перед «готово» — `verification-before-completion`; перед закрытием — `requesting-code-review`.

Настройка: `bash scripts/agent-setup.sh`. Если плагин недоступен — остановитесь.

## 2. Что это за репозиторий

`crumbru/business-online-sdk-php` — standalone PHP SDK для API Бизнес.Ру (Class365).
Библиотека, а не приложение: её подключают другие проекты через Composer.

Пакет: `business-ru/business-online-sdk-php`, PHP ^8.0, PSR-3/PSR-16/PSR-18, `ext-curl`,
`ext-json`. Публичный API — `src/Client.php` и вспомогательные HTTP-классы.

## 3. Границы и владение

- Не добавлять сюда CRM-логику, UI, миграции и инфраструктуру.
- Не менять поведение публичного API без мысли о совместимости потребителей.
- Не вызывать реальный Business.Ru API в тестах и проверках.
- Репозитории-потребители (`crm-backend`, `crm-bot` и др.) не меняются в рамках задачи SDK.

## 4. Стек и структура

```
src/Client.php          # публичный клиент
src/Http/               # Request/Response/Uri/Stream и др.
src/Exceptions/         # исключения SDK
src/SimpleHttpClient.php
src/SimpleFileCache.php
composer.json           # PSR-4: bru\api\
README.md               # использование и примеры
```

## 5. Команды

```bash
composer validate --no-check-publish
```

**Тестов и CI в репозитории нет.** Не выдавайте `composer validate` или ручной запуск
примера за тесты. Если добавляете тесты — это отдельное изменение с инфраструктурой
и согласованием.

## 6. Рабочий цикл

1. Нетривиальное изменение публичного API — сначала план и оценка совместимости.
2. Ветка от `master`; один PR — одна цель.
3. Коммиты — conventional commits, описание по-русски.
4. Перед PR: `composer validate`, `php -l` для изменённых файлов, `git diff --check`.
5. Force-push — только с явного разрешения.

## 7. Документация

- `README.md` — единственная документация SDK: установка, примеры, ответы, примечания.
- Изменили публичный метод, сигнатуру или поведение — обновите README и примеры в том же PR.
- Не описывайте несуществующие методы и параметры.
- Новые документы — только по-русски.

## 8. Тесты и Definition of Done

- Тестового набора нет; это известное ограничение, а не повод считать изменение проверенным.
- Задача закрыта, когда `composer validate` проходит, изменённые файлы проходят `php -l`,
  README обновлён, в diff нет секретов и посторонних изменений.
- Для рискованных изменений опишите ручной сценарий проверки и его результат.

## 9. Безопасность

- Никаких реальных токенов, логинов и URL с credentials в репозитории, примерах и PR.
- Не выполнять live-запросы к Business.Ru с реальными данными.
- Не логировать токены и полные ответы API.
- Не ослаблять проверку TLS, таймауты и обработку ошибок ради «удобного» примера.

## 10. Чего не делать

- Не ломать обратную совместимость без отдельного решения и версии.
- Не добавлять зависимости без необходимости.
- Не пушить в `master` напрямую.
- Не писать документацию, задачи, тикеты, PR и коммиты на английском языке.
